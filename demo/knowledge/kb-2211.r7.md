# VPN certificate errors

Applies when the client reports `IKE_AUTH failed: certificate verify failed`,
`peer certificate expired`, or the connection drops within ten seconds of
authenticating.

## Diagnosis

1. **Read the certificate the client is presenting.**
   `vpnctl cert show --user <upn>` prints the subject, issuer and `notAfter`.
   If `notAfter` is in the past, the certificate expired — this is the root
   cause on most of these tickets. Stop here and reissue.
2. **Check the issuing CA chain.** `vpnctl cert verify --user <upn>` fails with
   `unable to get local issuer certificate` when the intermediate CA was rotated
   and the client never pulled the new chain.
3. **Check the client clock.** A device more than five minutes out of sync will
   reject a valid certificate. `vpnctl diag clock --user <upn>`.
4. **Check the concentrator.** Only if steps 1–3 are clean: an outage on the
   concentrator surfaces as a generic auth failure for every user at once. Look
   at the network status page before you call it a certificate problem.

## Resolution

Reissue the user certificate:

```
vpnctl cert reissue --user <upn> --profile corp-remote
```

The user must reconnect once for the new certificate to be installed. Reissue
takes up to four hours to propagate to the regional concentrators.

## Workaround while a certificate is being reissued

If the user cannot wait for propagation — travel, an on-call rotation, a
customer-facing incident — enable the legacy IKEv2 fallback profile for that
user only:

```
vpnctl profile assign --user <upn> --profile corp-remote-legacy --hours 8
```

The fallback profile authenticates with the pre-2023 shared credential instead
of a certificate. It expires automatically after the hours you pass. Full
conditions, the approval it needs and the audit note you must leave are in
**kb-1180**.

> Do not leave the fallback profile assigned once the reissued certificate has
> propagated. Remove it with `vpnctl profile clear --user <upn>`.

## Escalate when

- Step 4 shows the concentrator is down: this is an incident, not a ticket.
- The reissue command fails with `CA unavailable`.
- The same user has needed three or more reissues in thirty days.
